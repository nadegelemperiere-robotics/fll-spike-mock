1. The layout at a glance

The screen has four areas:

  • Top toolbar — robot & mat selectors and the action buttons.
  • Editor (left) — two tabs: Blocks and Python. Independent — the Python tab is not a live view of the blocks.
  • 3D simulator (right) — a top-down view of the mat with the robot. Above the mat: the hub display (5×5 matrix, side buttons). On the mat: a small live readout of every sensor.
  • Console (bottom) — every print() call from your program, plus info and error messages.

2. Picking a robot and a mat

Use the two dropdowns at the top of the toolbar:

  • Robot — picks a built robot model. The wheels, motors and sensors are loaded automatically; you cannot change them from inside the app.
  • Mat — picks a printed mat (FLL field, demo grid, etc.). The mat fills the floor of the simulator; the robot's color sensor reads pixels from this image.

Your last choice is remembered for the next time you open the page.

3. The action buttons

ButtonWhat it does
▶ Run Runs the program from the active editor tab. The robot starts moving on the mat. The button stays green; the status next to the robot/mat name changes to Running….
■ Stop Stops the program and stops every motor. Use this when the robot does something you didn't expect — you don't have to wait for the program to finish on its own.
⟲ Reset Sends the robot back to its starting position on the mat and clears the hub display. Does not change the program — your code stays untouched.
📂 Load Opens a file picker. Pick a .py file → loaded into the Python tab. Pick a .xml file → loaded into the Blocks tab. The active tab switches automatically.
💾 Save Saves the content of the active tab. From the Blocks tab you get a .xml file; from the Python tab you get a .py file. You can choose the file name.
📖 Help Opens the code examples page (movement, color sensor, gyroscope) in a new tab.
Run vs Reset: Run launches the program; Reset just teleports the robot back to its start. If you want to stop the program use ■ Stop, then Reset to put the robot back where it started.

4. The editor: Blocks vs Python

The editor has two tabs. They are independent editors:

  • 🧩 Blocks — drag & drop blocks from the left palette onto the workspace. Blocks generate Python automatically when you click Run.
  • 🐍 Python — type Python code directly. Anything you type stays in this tab, even if you switch to Blocks and back.

Switching tabs does not copy code from one to the other. The Run button uses whichever tab is currently active.

Variables & Lists: in the Blocks palette, My Blocks lets you create your own functions; Variables lets you create simple variables and named lists.

5. Repositioning the robot

You can put the robot anywhere on the mat before running the program:

  • Drag the robot with the mouse → moves it on the mat.
  • Shift + drag → rotates the robot in place.

The new pose becomes the robot's start pose. ⟲ Reset always returns the robot to this start pose, not to the original mat default.

On a Chromebook, Alt+click is intercepted by the system — that's why we use Shift for rotation.

6. The hub display

Above the mat, the hub display mirrors what your program does to the real hub:

  • 5×5 matrix — every light_matrix.set_pixel(x, y, intensity) call lights one of the 25 pixels. light_matrix.write("Hi") scrolls text. light_matrix.show_image(...) shows one of the built-in icons.
  • Power button (centre, between L and R) — its colour changes when your program calls light.color(light.POWER, color.RED).
  • Bluetooth ring (right-most) — same idea with light.CONNECT.
  • L  /  R buttons — click or hold them; the program reads the press time via button.pressed(button.LEFT).

7. The console

The black panel at the bottom shows three kinds of lines:

  • info / ok — what the simulator is doing (loading a mat, Pyodide ready, …).
  • log — anything you print() from your program.
  • err — Python errors (with the line number and the type of error).

The Clear button at the top-right of the console wipes it. The console is per-session — it disappears when you reload the page.

8. Typical workflow

  1. Pick a Robot and a Mat from the toolbar.
  2. (optional) Drag the robot to the start position you want.
  3. Build a program in the 🧩 Blocks tab, or write Python in the 🐍 Python tab.
  4. Click ▶ Run and watch the robot move.
  5. Something wrong? ■ Stop, then ⟲ Reset, fix the code, Run again.
  6. When you're done: 💾 Save to keep your work as a file, or just close the tab — the simulator remembers your last code automatically.
